## A genuine methodology self-catch, worth recording

The Auditor's first draft of its acceptance script checked outcome/status
badges with `"badge--outcome-GAP" in page.content()`. This passed for
**every** outcome, including wrong ones — `response_detail.html`'s own
inline `<style>` block statically declares all four `.badge--outcome-*`
and all three `.badge--*` status CSS rules on every response page
regardless of which one actually applies. The Auditor caught this mid-run
(an unrelated assertion failure forced closer inspection — nothing forced
the discovery structurally) and rewrote every such check to a real,
scoped DOM query (`.response-detail__status-row .badge--outcome-<X>`
element existence, not text/CSS containment, with an explicit assertion
that every *other* outcome's badge is absent, not just that the expected
one is present). This is exactly the class of defect the FORGE Auditor
contract's own non-vacuity discipline exists to catch — it happened in the
Auditor's own harness, not the product, but is recorded here because it
directly bears on how much weight this GREEN verdict can carry.

## Correction to the Auditor's own report

The Auditor's report flagged PID §28's live AI evaluation gate as "still
outstanding" — this is incorrect. The Auditor's own environment could not
reach the real Trinity gateway with a working credential (it found and
attempted to probe an unrelated persona's LiteLLM key,
`/srv/bagman-secrets/litellm_gateway_key` — a different project's secret,
not the Infosecurs one at `/srv/secrets/infosecurs/litellm_gateway_key`
on dell-debian — and correctly stopped when its own credential-exploration
guardrail blocked further probing), so it substituted a deterministic fake
gateway for its own run — a sound, clearly-documented judgement call for
driving the deterministic application pipeline end-to-end through a real
browser (steps 1-22, 24), but it does not and cannot independently exercise
the real model's own semantic behaviour (step 23's injection resistance
specifically, and interpretation quality generally). That gate is a
*separate* delivery requirement, and it is **already closed**: two real
`--gateway=live` runs against `trinity-core` on dell-debian, using the
correct HELM-provisioned credential, are documented in
`docs/evidence/M005-LIVE-EVALUATION.md` (landed via PR #31, merged to
`main` at the very commit — `9056bc5` — this audit itself evaluated). The
Auditor's own worktree, checked out at that exact SHA, already contained
that file; the note appears to have been written without cross-referencing
it against the live probe attempt's failure. This does not change the
`GREEN` verdict — every step within this audit's own actual scope (PID
§29) passed on genuinely real infrastructure — but the correction is
recorded here so the two delivery gates (PID §28 live evaluation, PID §29
real-browser acceptance) are not conflated in the closure record.
