## Finding 1 (PRODUCT RED basis) — `next_review_date` date pickers render blank to a real user

`policy/forms.py`'s `PolicyApprovalConfirmForm.next_review_date` and
`PolicyVersionEditForm.next_review_date` both used
`forms.DateInput(attrs={"type": "date", ...})` with `input_formats=
["%Y-%m-%d"]` (controls parsing on submit) but no `format="%Y-%m-%d"` on
the widget itself (controls rendering). With `LANGUAGE_CODE = "en-gb"`,
Django rendered the `value` attribute as locale-formatted `23/09/2027`
(DD/MM/YYYY) instead of the ISO `yyyy-MM-dd` an HTML5 `<input type="date">`
requires.

**Source inspection alone would pass this** — a value is present in the
markup. **Real browser reproduction proves the opposite**: computed DOM
`.value` property = `''` (empty), confirmed live on the approve-direct
page, with a matching explicit Chromium console warning naming the exact
malformed value. PID §18's "pre-filled but editable, not silently applied"
review-date default is computed correctly server-side but never visibly
appears to a real user.

## Finding 2 (secondary, accessibility) — duplicate HTML `id` attributes on the governance role-assignment page

`governance/views.py`'s `role_assignments` view instantiated
`RoleAssignmentForm` three times (once per role row) with no `prefix=`, so
all three rows rendered identical `id="id_person"` etc. Confirmed live via
`document.querySelectorAll('[id="id_person"]')` returning 3 elements —
`<label for="id_person">` on rows 2/3 resolved to row 1's field, not its
own. Did not block the audit script (selectors were scoped per
`<fieldset>`), but a real label-click/screen-reader user on rows 2/3 would
be affected.

## Finding 3 (secondary, PID-completeness gap) — no path to edit the Account Holder's own name/job title

PID §3 user outcome #4 states the Account Holder can "confirm/**edit**
their name and job title." Confirmed by full-repo grep: no view/form
anywhere wrote to an existing `OrganisationPerson.full_name`/`job_title`
for the Account Holder's own row after creation — the governance
role-assignment page only displayed it. A real, unimplemented half of a
PID-declared user outcome, not just polish.
