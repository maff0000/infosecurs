**L1 — MEDIUM — The unbroken-text overflow defect class (G2 → H2 → J1) recurs a
fourth time, on two further surfaces neither prior round reached.**

- Evidence detail page: a realistic 44-character unbroken hostile title overflows the
  page (`scrollWidth=425` vs `clientWidth=375`, ~13%) — the page's `<h1>` title has no
  `overflow-wrap` rule.
- Key Asset detail page: a genuinely realistic unbroken 300+ character run (e.g. a
  pasted token/hash/URL) in the asset's description overflows the page severely
  (`scrollWidth=3340` vs `clientWidth=375`, ~9×) — the description `<p>` has no
  `overflow-wrap`/`word-break` protection at all.
- Confirmed by direct source inspection (`grep overflow-wrap static/organisations/css/
  app.css`): only `.card-list__title` and `.badge` carry this protection anywhere in
  the shared stylesheet — ordinary heading/paragraph text on detail pages was never
  covered by G2, H2, or J1's own scope. Not Critical/High — content remains reachable
  via ordinary page scroll, nothing hidden or non-functional, same disposition tier as
  its three predecessors — but it demonstrates that patching each specific reported
  location has not yet become a systemic guarantee against this recurring defect class.

**K1 — MEDIUM — AI-drafted SUPPORTED-outcome wording fabricates claims of
verification/evidence that don't exist; I2's fix does not cover this outcome.**

- `backups=yes` (customer-stated, zero evidence items attached): drafted text claimed
  "the current security record includes active supporting evidence for this control" —
  false; the same response's own "Why this answer?" panel shows zero evidence items.
- `patching=yes` (customer-stated, zero evidence items attached): drafted text claimed
  the state was "confirmed by the current operational record" and that "the assurance
  label 'Customer stated' reflects documented and verified patching practices" — a
  materially false claim that directly inverts what "Customer stated" means
  (self-reported/unverified, by definition).
- Confirmed by direct source inspection (`questionnaire/services.py`'s
  `_initial_current_answer_text`, its own docstring): the I2 fix is explicitly scoped

  over-generalise; SUPPORTED (and GAP/NOT_APPLICABLE) still pass the raw, unmoderated
  AI draft straight through to the customer. The deterministic SUPPORTED/GAP outcome
  itself stays correct (true per canonical state) — this is a wording/evidentiary
  overclaim on the one outcome most likely to be copied verbatim into a real vendor
  questionnaire without a second look, since the badge already reads "supported."
